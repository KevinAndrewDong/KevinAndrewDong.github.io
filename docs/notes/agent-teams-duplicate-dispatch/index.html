修复 Agent 调度竞态：防止指导消息触发重复派发

指导消息把成员唤醒时，异步空闲回调还没结束。一次状态轮询把仍有效的执行误当成待恢复。

2026-11-19上游 PR ↗
我的贡献
保留跨指导轮次的执行 ID，并用重复派发和进程重启两个场景验证其生命周期。
验证
受控竞态 3 次复现重复派发，修复后 3 次均只派发一次；重启仍能恢复。

空闲不等于执行已经结束

成员进入空闲后，插件还要异步读取会话状态。如果此时指导消息触发新的运行事件，旧实现会顺手清掉暂存的执行 ID。队长轮询时看到任务仍在进行、却找不到这次执行的身份，就错误地把同一任务发给成员第二次。

修复是保存身份，不是屏蔽轮询

同一个任务跨指导轮次保留执行 ID；真正的进程重启仍按已有恢复规则重新派发。回归不只数消息，还断言任务状态、尝试编号与 ID，以区分“多收到一个包”和“真的开始了又一次执行”。

证据来自 macOS 上的真实无界面 Harness CLI，模型输入使用脚本适配器控制。两个宿主版本上检查了在途重复和重启恢复；不能把受控模型输入说成真实模型行为。
