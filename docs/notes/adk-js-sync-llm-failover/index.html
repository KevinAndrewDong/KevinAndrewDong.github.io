TypeScript · 模型路由

修复 ADK JS 模型路由：让首个输出前的同步异常进入回退策略

ADK JS 的路由能处理首个输出之前的异步错误，却漏掉了初始化时同步抛出的异常。

2026-10-28上游 PR ↗
我的贡献
将模型调用纳入同一个异常边界，沿用已有的回退、重试与取消策略。
验证
同一组 Mac 测试中，修复前 4 项失败，修复后 59 项全通过。

一个模型路由器按顺序调用候选模型。第一家还没输出任何内容就失败，且错误符合现有回退策略时，路由器应该尝试下一个候选，而不是直接结束请求。

调用时抛错和读取流时抛错，不是同一个时机

ADK JS 的 RoutedLlm 已经能处理 Promise 被拒绝，以及读取流时在首个输出前抛出的错误。但调用 delegate 初始化响应的那一行在 try 之外。调用如果当场抛错，程序连返回的 Promise 或迭代器都没拿到，错误也就没有进入现成的路由决策。

判断这类问题，可以先区分三个边界：

失败时机 应怎样处理
调用 delegate 当场抛错 交给既有路由策略决定是否回退
Promise 拒绝，或流在首个输出前报错 继续走原有路由策略
已经产生输出后报错 保留原有行为，不把切换模型当成无条件补救

我的修改

在 ADK JS #1153 中，我把 delegate 调用移入现有的 try。这样三个不同入口的错误可以交给同一处规则判断。没有新增一套重试逻辑，也不把所有 AbortError 简化成同一个决定。

关键不是多包一层 catch，而是让初始化和读取响应共享同一个异常边界，同时保持输出前后的分界不变。

如何验证

用同一组测试在 Mac 上做对照：未改动的生产源码是 55 通过、4 失败；修复后 59 通过。测试验证的是路由行为，没有把云端复跑叠加成额外用例，也没有测试真实模型服务中断、手工端到端流程或完整取消竞态矩阵。

此 PR 已合入，开发中使用了 Codex。
