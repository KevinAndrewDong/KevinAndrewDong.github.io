“未声明”和“无”，为什么在 Agent 界面里不能合并？

  1. 1. 先看接口保留了什么
  2. 2. 为什么只改弹窗
  3. 3. 怎么知道改对了

在 DeerFlow 导出一个 Skill 时，弹窗会列出它声明的工具和凭据。旧版本里，一份明确写了空列表的配置，会让其中一行显示成空白。用户只看到这一行没文字，却不知道是没有声明、明确不需要，还是页面没读到数据。

我提交的 DeerFlow #5659 处理的是这处展示问题。以下梳理基于公开 PR 和发布源码，PR 中有 Codex 协助。

先看接口保留了什么

Skill 元数据进入导出清单，再由接口交给 React 弹窗。对弹窗来说，工具和凭据各有三种状态：

接口值 弹窗应显示 含义
null 未声明 Skill 没有显式声明这一项
[] 无 Skill 显式声明了空列表
非空数组 逐项展示 列出声明的工具，或凭据名称和必需／可选状态

这里展示的是凭据名称，没有展示密钥值。工具列表为空也不等于 Agent 的全部工具都被禁用；这一改动没有碰运行时的权限规则。

为什么只改弹窗

旧代码大致是 allowedTools?.join(", ") ?? "未声明"。当输入是 []，join 返回空字符串，?? 不回退。换成 || 虽然不再空白，却会把显式空列表显示成“未声明”。

接口已经保留了三态，所以修复只在展示层做明确分支：先判 null，再判数组长度，最后走原有的非空格式化。两个字段都遵循这个规则，中英文文案也一起补齐。配置格式、导出内容和后端接口不用随之改变。

怎么知道改对了

新增三个参数化 DOM 场景，每个场景同时断言工具和凭据。PR 记录弹窗相关套件共七项通过，涵盖新增三项和原有四项。独立评审 也核对了从元数据到 UI 的路径，并报告聚焦测试通过。

我把证据限定在这里：测试模拟了请求，断言用英文文案；没有据此证明中文浏览器流程、保存后重开或导出后再导入。另一个容易看错的地方是版本：v2.1.0 虽在 PR 合入后发布，源码仍是旧逻辑；v2.2.0 才是这里首个核实包含这项修复的正式版本。

以后再遇到界面里的空白，我会先把 没提供、明确为空、有值 分开看：如果上游把这三种状态交给了界面，就不该为了少写一个判断，让用户替代码猜是哪一种。
