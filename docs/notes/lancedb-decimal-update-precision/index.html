Python / Arrow · 数据精度

保留 LanceDB 表更新中的高精度 Decimal 数值

表更新不接受 Python Decimal 或 Arrow decimal scalar；不恰当的中间表示还会丢失有效数字。

2026-10-10上游 PR ↗
我的贡献
把 Decimal 转为带引号的定点文本，由原生层按目标列类型转换，拒绝非有限值。
验证
真实原生扩展上 33 个新增回归修复前全失败、修复后全通过，另有 16 个既有用例通过。

要保留的是目标列的十进制精度

高精度金额或计量值不应该先经过二进制浮点。在 LanceDB 的更新路径中，Decimal 值原先没有转换器；改成不带引号的 SQL 数字虽然看起来更接近原值，却可能在解析阶段被舍入。

让本来就知道列类型的一层做转换

我的改动把有限 Decimal 格式化为不丢数字的定点文本，再交给原生层按目标 decimal 列转换。对 NaN 和无穷值明确报错，不把它们当成合法数据。

用源码构建出的 Mac 原生扩展验证了 Python 和 Arrow 两类输入，覆盖 decimal128、decimal256、符号、指数和低 Python 十进制上下文精度。原生对照也验证了同一高精度值的未加引号数字会被舍入。这不是对所有更新表达式或平台的保证。

本文据已合入的上游 PR整理。
