PyTorch · 数值类型

对齐 TorchEBM 时间步编码类型，支持 float64 前向计算

时间步编码与后续线性层权重可能使用不同 dtype，float64 前向因此遇到类型冲突。

2026-09-07上游 PR ↗
我的贡献
在编码交给 MLP 的边界对齐权重 dtype，保留既有 float32 输出。
验证
新增 float64 回归；PR 记录全套测试 1756 通过、80 跳过、21 未选。

问题在两个张量约定的交界处

时间步编码和 MLP 各自构造张量，单独看都合理。但模型改用 float64 后，编码仍可能是另一种 dtype，第一层线性变换就接不起来。把整个模型强制转成同一类型，会把修复扩展到调用者本来有意控制的地方。

在消费边界对齐

我在正弦时间步表交给 MLP 前，按该层权重的 dtype 转换输入，保留现有 float32 输出。回归验证 float64 前向和 float32 行为不变。

公开测试结果说明覆盖到这个局部契约，不代表所有设备、精度组合或实际训练负载均已验证。
